# 解析器补齐与模型对比

本次实现：统一单一完整规划协议；按工具拆分模型输出 schema，编译到兼容的执行协议；条件清单区分必需、偏好、禁止并关联工具步骤；条件贯穿网页/REST/MCP、图片评分和缓存；mood 分流到 POI、地理/映射要素和视觉偏好；无效结构/程序最多修复一次，45 秒总截止；解析模型独立配置。

Nature/Adventure 的地理来源是可选候选来源；Waterside 使用水边过滤的命名候选与岸边采样并集。显式业务目标不会混入无关风景候选。可选地理来源不可用时保留其他候选，必需地理条件不可悄悄丢弃。条件分支通过图片的 eligibleSearchPaths.requirementIndexes 隔离；已映射的半径/地址不用图片重新证明。

## 评测和模型选择

同一最终 prompt 对 41 个合成输入分别调用模型；只测规划，不执行提供商/评分。当前规则复核保存的原始结果：

| 模型/推理档 | 规则通过 | 中位耗时 | P95 |
| --- | --- | --- | --- |
| gpt-6-luna / 未显式指定 | 40/41 | 7.53s | 16.09s |
| gpt-6.1-sol / 未显式指定 | 40/41 | 10.69s | 20.91s |
| gpt-6.1-sol / low | 38/41 | 7.54s | 28.25s |
| gpt-6-astra / low | 38/41 | 8.26s | 40.03s |

Astra 完整批次中 38 个返回方案均通过有限检查，另外 3 个是 API 超时，没有返回可检查的方案。前置 8 个复杂输入对 Astra 的试测，经校准规则复核为 8/8。Sol low 有一次 Nature 未补地理候选，也有 API 超时。Luna/Sol 的剩余单次失败在校准后均为 API 超时。

部署选择 Astra low 是结合用户要求更强规划能力、复杂输入中的语义表现及独立配置的产品选择；本样本没有证明它统计上优于其他模型。其长尾仍需关注，不能宣称端到端十秒目标已经达到。更强模型也不能保证任意输入都准确。

原始报告未覆盖。复核修正了评测器过严的三类规则：水边可以用 lake/sea/river 的 OR；排除湖边所需的几何查询不是正向湖边限制；严格大于高度的微小 epsilon 可接受。可选过滤结果与原始业务候选的并集不算硬限制。

评测期间工具引用校验曾短暂尝试要求条件的每个 stepId 都对应同一种 route，随后回到“至少一个实际实现工具，允许关联的合并/混合步骤”，因为一个条件可能通过来源、过滤、合并共同实现。Sol low 批次发生在该尝试期间，因此它的耗时不应作为严格公平的模型优劣结论。最终 Astra 完整批次使用最终引用校验。

319 项 Python 测试、59 项前端 Node 测试及 TypeScript 编译通过，覆盖兼容路径、分支隔离、工具参数、有限修复、提供商错误不重试、条件强弱与缓存隔离、可选来源降级。
